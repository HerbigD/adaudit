# 真实跑数手册

> 给**在本机跑真实 API** 的人用。Claude 侧永远没外网，所有真实调用只能你跑。
> 每一节的结构一样：**命令 / 预期输出 / 验收点 / 常见失败**。照抄即可，不需要读代码。

---

## 0 · 开跑前（一次性，两分钟）

### 0.1 确认配置是真实态

```bash
cd ~/github/adaudit
grep -E "APP_ENV|PROVIDER" .env
```

要看到：

```
APP_ENV=dev
VLM_PROVIDER=qwen
LLM_PROVIDER=qwen
SEARCH_PROVIDER=dashscope
```

任何一项是 `mock` 都跑不出真实产物 —— 脚本会自己拦下来并告诉你改哪行（`guard_real()`）。

### 0.2 确认熔断预算

```bash
cd api && python3 -c "from services import usage; print(usage.snapshot())"
```

看 `remaining`。日预算 500k token，跑完本手册全部五项大约用 **2–4 万 token**，
远在预算内。`exceeded: true` 就说明今天已经烧穿了，明天再跑或调 `DAILY_TOKEN_BUDGET`。

### 0.3 一句话安全网

跑测试**不会**产生真实调用 —— `tests/conftest.py` 强制把四个 provider 按成 mock
并在 `httpx` 上挂了出站熔断。所以 `pytest` 随便跑，不花钱。

⚠️ 但**本手册里的命令会真的花钱**，因为它们是直接调脚本，不走 pytest。

## 1 · 慢路径出 `direct_verified`（带真实 URL + 单条成本）

### 命令

```bash
cd api
python3 scripts/day6_real_run.py --ad ~/imperial_foodad/"# Images - food only"/India/<某张牛奶或麦片图>.jpg
```

高置信直出、走不到搜索时，加 `--force-search` 逼它走慢路径：

```bash
python3 scripts/day6_real_run.py --ad <图片> --force-search
```

`--force-search` 把 `DIRECT_THRESHOLD` 临时抬到 1.01，任何图都会被判"置信不足"
从而进入取证链路。**它只改本次进程内的阈值，不写 .env。**

### 预期输出

`data/day6/ad_<文件名>.json`，里面应当看到：

```json
{
  "route_1": "search",
  "search_status": "ok",
  "route_2": "direct_verified",
  "evidence": [{"source_url": "https://...", "nutrients": [...]}],
  "cost": {"tokens_in": ..., "tokens_out": ..., "cost_usd": ...}
}
```

### 验收点

- [ ] `route_2 == "direct_verified"`
- [ ] `evidence[0].source_url` **不是空字符串**（见下方"常见失败 A"）
- [ ] `cost.tokens_in > 0`（真的调了模型，不是走的兜底）
- [ ] trace 里 `adjudicate_with_evidence` 的 `adapter` **不是** `rule-fallback`

### 常见失败

**A. `evidence` 全空但没报错 —— 最需要你盯的一条。**
百炼内置联网返回的 `search_info.search_results` 字段形状我是照文档写的、**没跑过真的**。
字段名对不上时解析会静默返回空列表，链路照常跑完，只是没有证据。
**所以第一条真实 Evidence 出来后，务必确认 `source_url` 不是空字符串。**
如果是空的，把 `data/day6/ad_*.json` 里的 `raw_search_response` 贴给我，我改解析。

**B. `route_2 == "human"` 而不是 `direct_verified`。**
看 `search_status`：`degraded` 说明抽到了读数但换算不出 per-100g；
`conflict` 说明两个来源数字打架。都不是 bug，是设计好的降级，换张图再试。

**C. `adapter == "rule-fallback"`。**
说明真实 LLM 裁决失败了，退到了本地规则。看 trace 里的 `fallback_reason`。

## 2 · 混淆对冒烟（≥3 张）

### 命令

```bash
python3 scripts/day6_real_run.py --confusion <混淆对图片目录>
```

目录里放 ≥3 张落在混淆对上的广告。手头没有就从切分集里挑：

```bash
head -20 api/data/splits/ablation_manifest_ids.csv   # pair 列就是它属于哪一对
```

### 预期输出

`data/day6/confusion.json`，每张一条：初判叶子 → 重裁决叶子 → 是否改判。

### 验收点

- [ ] ≥3 张跑完
- [ ] **改判方向正确**：改判后的叶子应当落在同一混淆对的另一侧
      （如 2↔12、5↔19），而不是跳到无关类别
- [ ] 每张都有 `evidence`，且裁决理由引用了 Evidence id

### 常见失败

改判方向跳到对外的类别 → 大概率是抽取拿错了营养素。
看 `evidence[].nutrients` 里的 `nutrient` 字段是不是 `saturated_fat` 被当成了 `fat`。

## 3 · OCR 五语种冒烟（en / hi / bn / ur / si 各 1 张）

### 命令

```bash
python3 scripts/day6_real_run.py --ocr-smoke <五语种图片目录>
```

### 预期输出

`data/day6/ocr_smoke.json`：每张的 `brand` / `product_name` / `ad_language` / `country`。

### 验收点

- [ ] 五张都跑完，无异常
- [ ] `brand` 与 `product_name` **人工核对**正确率（这一项没法自动判，你看图对答案）
- [ ] `ad_language` 与实际语种一致
- [ ] 本土文字品牌：`brand` 里**同时保留**拉丁转写与本土文字（prompt 有这条要求）

### 常见失败

`name_brand_identifiable: false` 且 `brand: null` —— 图太糊或确实没有品牌。
这不是失败，是设计好的行为（无锚点 → 转人工）。记下来即可。

## 4 · 熔断实调

### 命令

```bash
python3 scripts/day6_real_run.py --fuse-test
```

### 预期输出

```json
{"verdict": "PASS 熔断生效：真实调用在发出前被拒", "refused": true}
```

### 验收点

- [ ] `verdict` 以 **PASS** 开头
- [ ] `refused: true`
- [ ] 你**当日真实账本没有被污染** —— 该脚本用独立临时账本，跑完
      `python3 -c "from services import usage; print(usage.snapshot())"` 的数字不应变

### 常见失败

**`SKIP mock 模式下测不了熔断`** —— 你在 mock 下跑的。
mock provider 在熔断之前就抛 `VLMError`，那不是熔断失效，是这一态根本测不了。
把 `LLM_PROVIDER` 改成 `qwen` 再跑。

## 5 · SSE 在真实秒级延迟下的 broker 重放复验

真实调用每步要几秒，正好用来验"页面晚连上也不丢事件"。

### 命令

```bash
# 终端 1
cd api && uvicorn main:app --port 8000
# 终端 2
cd web && npm run dev
```

浏览器打开 `http://localhost:3000`，上传一张图 → 立刻跳到审计页。
**然后在 Agent 还在跑的时候刷新页面。**

### 验收点

- [ ] 刷新后时间线**从第一步开始完整重放**，不是从刷新那一刻开始
- [ ] 三态可见：进行中（蓝点脉冲）/ 完成（绿点）/ 兜底（黄框）
- [ ] 跑完后徽标显示"联网搜索取证"

### 常见失败

刷新后时间线是空的 → broker 的 channel 被提前回收了。
把 audit_id 给我，我看 `services/broker.py` 的 `close` 时机。

## 6 · 缓存二次免搜索（可选，不花钱）

第 1 节跑完后，**同一个产品**再跑一次：

```bash
python3 scripts/day6_real_run.py --ad <同一张图或同产品的另一张图>
```

### 验收点

- [ ] trace 里**没有** `web_search` 节点
- [ ] `cache_lookup` 的 summary 是"缓存命中…免搜索"
- [ ] `cost.tokens_in` 明显低于第一次（省掉了搜索与抽取两次调用）
- [ ] 页面时间线上"③ 联网搜索"显示**已跳过**（虚线灰框），右上角徽标变成"缓存命中 · 跳过搜索"

### 常见失败

**第二次仍然搜索了**，且 `cache_lookup` 显示 `best score=0.75`。
0.75 这个数字很特别：它 = 品牌精确匹配 0.55 + 名称完全重叠 0.20，**语义分为 0**。
说明向量库没读到档案。Day7 修过一次跨进程不刷新的缺陷；如果还出现，
把 `data/chroma/fallback.json` 和 audit_id 一起给我。
